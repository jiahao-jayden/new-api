# 渠道折扣与人民币显示

## 唯一计价公式

同步的模型价格是原价，不因渠道设置改变：

`实际消耗 = 原价对应的用量费用 × 实际执行渠道的折扣倍率`

- 渠道编辑中的 `3` 表示三折，存储为 `billing_discount: 0.3`；`0.3` 折存储为 `0.03`。
- 倍率必须大于 0 且不超过 1；未配置为 1，即原价。
- 原有分组字段保留用于渠道路由和兼容已有 API Key，不叠加分组或用户分组价格倍率。
- 普通用户界面不再显示或选择业务分组。持久 API Key 的创建、编辑、状态更新以及注册自动创建，统一保存到 `default`，关闭跨分组重试；前后端均执行此规则。
- 普通用户模型目录、模型选择与 Playground 使用 `default` 的可用渠道。旧网址或缓存中的分组不会改变实际请求；管理员保留渠道／路由诊断入口。
- 自动同步价格的路径保持不变；同步后读取到的价格就是原价，不再次反推所谓官方价。
- 请求重试时刷新渠道折扣，必要时补足预扣。结算使用实际成功渠道；异步任务保存提交时的价格和折扣。
- 新消费记录的 `pricing_source=channel`、`channel_discount` 明确标记实际计价来源。历史记录不改写。

## 模型广场

- 仅统计用户可访问且启用的渠道，同一渠道不会因多个分组重复计数。
- 单渠道：显示原价、折后输入／输出价格和折扣。
- 多渠道：卡片显示最低折扣和最低调用价，详情显示折扣及调用价格范围。
- 没有可用渠道时不展示虚构的优惠。
- 模型的缓存、工具、音频和动态计价仍沿用原来的计价结构，同样只应用一次渠道折扣。

## 币种与充值

- 内部账本不改：仍使用原版美元基准的整数额度。原有余额、历史流水和额度单位不重算。
- 默认以人民币展示；用户在个人资料切换美元，只改变当前浏览器、当前账户的显示偏好。
- 人民币展示额 = 美元基准额 × 后台原有 `USDExchangeRate`。原价和折后价都通过同一汇率转换。
- 新人民币充值请求使用 `payment_amount_cny`，不是原版美元整数数量 `amount`；两个字段不得同时提供有效值。
- 输入 ¥1500 表示实付 ¥1500；到账额度 = 1500 ÷ 汇率 × 原有额度单位，按统一安全精度规则取整。
- 新人民币充值不再叠加原来的充值单价、分组充值倍率或预设金额折扣。
- 新订单使用一个可空的 `credited_quota` 字段冻结到账额度，避免支付期间汇率变化影响回调到账。旧订单该字段为空，保留原有解释。
- 人民币支付最多两位小数；异常数值、低于最低金额或超出账本上限的请求被拒绝。
- Stripe 与易支付支持新的人民币请求；Stripe 以人民币分为单位创建固定总金额的 Checkout，禁用该新路径的促销码和自动换币。旧客户端及其他未迁移支付商保留原请求协议，不对小数数量做静默截断。
- 支付回调验证签名、币种／金额和订单状态后，在同一事务中入账；重复通知不重复充值。失败需返回失败响应，使支付商能够重试。

## 本地验证与上线边界

1. 开发测试只使用生产备份恢复出的独立本地工作库。原始备份保存在 Git 外的私有目录。
2. 工作库中的线上密钥、支付配置和后台任务先隔离，再启动本地服务；模型调用和支付以本地模拟验证，不调用真实付费服务。
3. 上线前由管理员确认每个渠道折扣。**旧分组优惠不再计费，未设置渠道折扣会按原价收费，不可未经确认直接部署。**
4. 上线前另做最新生产备份，审核代码并执行兼容性迁移。只增加可空充值额度字段；不清空、不重算原来的余额和记录。
5. 不把本地测试数据库覆盖回生产。生产仍持续产生用户、充值和调用记录，本地快照不能作为回写来源。
6. Stripe 真实收款能力还需商户在测试模式确认支持人民币结算流程；本地模拟通过不等同于真实支付渠道验收。

### default 路由迁移

本地已对独立工作库执行一次迁移，并另存迁移前快照：

- 在原 `GroupRatio` 注册 `default: 1`，在 `UserUsableGroups` 中启用 `default`，关闭旧注册自动分组选项。
- 将已有 API Key 的 `group` 统一为 `default`、`cross_group_retry` 设为 `false`；密钥本体、所有者、状态、额度、模型白名单、IP、有效期均不变。
- 为现有渠道增加 `default` 路由及相应模型能力，保留原渠道状态、优先级、权重、折扣和旧路由。旧路由暂不删除，避免影响历史任务和管理员诊断。
- 不改变用户角色／用户组、历史账单或模型定价。用户界面隐藏分组，不代表移除管理员的访问控制。

将来上线时，在最新生产备份之后，需要针对当时的密钥和渠道重新审核、执行上述迁移，并刷新令牌、配置、渠道及模型目录缓存。**不能只部署固定 default 的代码而不补齐渠道路由，也不能直接上传本地数据库。** 如果生产存在明确禁止访问 `default` 的权限设置，必须先人工解决冲突，不能绕过限制。

Stripe 协议依据：[Checkout 参数](https://docs.stripe.com/api/checkout/sessions/create)、[订单履约](https://docs.stripe.com/checkout/fulfillment)。保留本项目既有 SDK 版本，避免无关的接口升级。
