# DOT API UI 设计规范

版本：1.7
状态：实施基线
适用范围：`web/default` 的公共页面、登录页、认证后工作台、管理后台、弹窗与细分组件

## 1. 设计原则

### 1.1 真实内容优先

视觉参考只定义信息层级、布局节奏、颜色和交互表达，不定义产品功能。页面只能呈现当前代码和接口真实提供的内容；不得因为参考图出现了某个指标、配额、项目、节点或状态而新增数据、入口、文案或业务行为。

### 1.2 工作台而非营销页

界面围绕查找、配置、监控和执行任务组织。减少装饰性容器、重复标题和无意义的选择器；让主要任务在首屏形成清晰的阅读路径。

### 1.3 清晰、克制、可预测

每个页面只保留一个主标题、一个主操作区域和一套内容分组。交互控件具有稳定的高度、焦点、禁用和错误状态；管理员专属能力继续遵循既有权限判断。

页面结构不是业务契约。现有排版出现卡片套卡片、工具区和内容区混杂、信息层级重复或移动端难以阅读时，可以拆分组件、调整顺序和重建栅格。重排必须保持所有既有字段、操作、状态、权限判断、接口调用和文案不变，不得用纯前端占位补出后端不存在的能力。

### 1.4 用留白和底色建立层级

默认不使用阴影，也不依赖描边堆叠界面层级。页面优先通过留白、排版、浅色内容面和语义色区分信息；只有键盘焦点、错误状态、表格必要分隔、浮层边界等无法仅靠布局清楚表达的场景，才使用克制的描边或阴影。

图标直接与标题、标签或操作并列，不使用带底色的方块、圆形或渐变容器包裹。图标颜色服务于层级和状态，不作为独立装饰。

### 1.5 响应式是同一套系统

桌面端采用侧边栏工作台结构，窄屏将侧边栏变为抽屉；表格转换为可读的移动卡片，工具栏允许换行但不产生横向溢出。

## 2. 视觉基础

### 2.1 Material 3 动态色系统

颜色不得按页面临时指定，也不得通过 `color-mix` 或人工挑选一组相近色来模拟 Material 3。系统使用 Google 官方 `@material/material-color-utilities@0.4.0`，按 Material 3 Tonal Spot（2021 规范、标准对比度）从种子色生成 HCT 调色板和完整语义角色。种子色只决定色相与调色板性格，不直接作为按钮、文字或容器的最终颜色。

生成脚本是颜色的唯一来源：

```bash
bun run theme:generate
bun run theme:check
```

生成结果写入 `src/styles/material-colors.generated.css`。修改种子色或角色映射后必须重新生成，禁止直接编辑该文件。`theme:check` 同时检查生成文件是否过期，并验证主色、容器、表面、反色表面和错误色的前景组合均达到 WCAG AA `4.5:1`。

| 角色组                                     | Light 关系               | Dark 关系                  | 用途                       |
| ------------------------------------------ | ------------------------ | -------------------------- | -------------------------- |
| `primary / on-primary`                     | 深主色 / 白色前景        | 浅主色 / 深色前景          | 主操作、链接、焦点         |
| `primary-container / on-primary-container` | 浅主色容器 / 深色前景    | 深主色容器 / 浅色前景      | 选中态、分段控件、强调区块 |
| `secondary`、`tertiary`                    | 同源次级、补充色调色板   | 同一角色在暗色调上的对应值 | 次级操作与数据区分         |
| `surface`                                  | Neutral 高色调           | Neutral 低色调             | 工作区主题内容面           |
| `surface-container-lowest`                 | Neutral `T100`           | Neutral `T4`               | 中性页面画布、最高对比内层 |
| `surface-container-low / container`        | Neutral `T96 / T94`      | Neutral `T10 / T12`        | 工具栏、卡片与默认容器     |
| `surface-container-high / highest`         | Neutral `T92 / T90`      | Neutral `T17 / T22`        | 控件、hover 与更高层容器   |
| `outline / outline-variant`                | Neutral Variant 中间色调 | Neutral Variant 暗色对应值 | 必要边界和轻分隔           |
| `inverse-surface / inverse-on-surface`     | 深反色面 / 浅前景        | 浅反色面 / 深前景          | Snackbar 等反色反馈        |

组件只消费语义角色。`Container` 角色用于选中态、筛选标签和低强调区块，实色角色只用于主操作与明确状态。禁止在组件中使用 `blue-*`、`green-*`、`amber-*` 等原始颜色类，也禁止把 `secondary-container` 当作 `secondary` 使用。

Material 3 只内建 `error` 状态。产品需要的 `success`、`warning`、`info` 由固定语义种子通过同一 HCT Tonal Spot 算法生成，不能手写明暗色。生成前必须使用 Material Color Utilities 的 `Blend.harmonize` 将语义种子向当前页面来源色调和，再从调和结果生成完整的实色、前景色、容器色和容器前景色；这样状态含义稳定，同时不会像一组外插的交通灯颜色脱离页面色调。

数据可视化使用 12 色动态色板。色板由当前工作区的 `primary / secondary / tertiary / error` 与调和后的 `success / warning / info / violet` 动态角色组成，并提供同源主色的补充 tone。业务图表不得回退到 VChart 默认色板或页面内手写的分类色数组；供应商品牌识别色、支付品牌色和代码语法高亮属于明确例外。图表网格、标签、轮廓和点背景分别读取 `outline-variant`、`on-surface-variant`、`outline` 和 `surface-container-lowest`。

Canvas 图表无法像普通 DOM 一样自动响应 CSS 变量。主题亮暗、颜色预设或页面工作区发生变化时，必须先让对应的 body attribute 与根节点主题类落地，再在下一动画帧读取计算后的动态角色、重建 spec 并更新图表 key。禁止在 render 前缓存旧工作区颜色。

### 2.1.1 页面级动态色

认证后页面必须同时继承所在侧边栏工作区的强调色和同源中性色面。路由只负责选择工作区色调，组件仍只读取 `primary`、`secondary`、`tertiary`、`surface-container-*` 等语义角色，不得判断路由后写入颜色类。

| 工作区                  | 路由范围                                                                 | HCT 种子  | 页面用途                         |
| ----------------------- | ------------------------------------------------------------------------ | --------- | -------------------------------- |
| `platform`              | 公共与平台入口                                                           | `#0B57D0` | 平台导航、模型广场与默认回退     |
| `chat`                  | `/playground`、`/chat*`、`/chat2link`                                    | `#008577` | 对话、游乐场及其交互控件         |
| `general`               | `/dashboard*`、`/keys*`、`/usage-logs*`                                  | `#52677D` | 日常数据、密钥和日志工作区       |
| `personal`              | `/wallet*`、`/profile*`                                                  | `#F9AB00` | 钱包、个人资料及账户相关操作     |
| `admin`                 | `/channels*`、`/models*`、`/users*`、`/redemption-codes*` 等管理员工作区 | `#D93025` | 管理对象、危险度较高的配置工作区 |
| `system-administration` | `/system-settings*`                                                      | `#188038` | 系统级配置与运维设置             |

侧边栏背景读取当前工作区的 `surface-container-low`，页面画布读取同一工作区的 `surface-container-lowest`。因此浅色模式下画布保持中性白色，侧边栏则呈现由当前 HCT 工作区种子生成的浅色调；切换到密钥、钱包或管理页面时，会分别得到同源的浅蓝灰、浅琥珀或浅珊瑚背景，而不是路由内手写的颜色。

侧边栏选中态读取固定的 `--nav-*-container` 角色，页面内容读取当前工作区映射后的标准 M3 角色。这样切换页面时，钱包的按钮、页签、输入选中态和内容表面会与琥珀导航保持一致，同时其他导航分组仍保留自己的固定识别色。禁止按路由手写浅蓝、浅黄等侧边栏颜色；新增工作区时必须先在动态色生成器中定义种子，再消费生成的语义角色。

用户在主题设置中主动选择颜色预设时，该预设作为明确的个人偏好覆盖默认工作区色调；恢复默认预设后，页面重新跟随所在导航工作区。

`surface / surface-container-lowest / low / container / high / highest` 必须来自当前工作区种子生成的同源 Monet Neutral 调色板。页面画布使用 `surface-container-lowest`，在浅色模式下呈现中性白色；主内容卡、表格和图表使用带有工作区色相的 `surface`，工具块和次级卡使用 `container`，输入、静止标签和可选项使用 `high`，hover 使用 `highest`。深色模式保持相同层级关系，由最深画布承托略亮的主题内容面。不得用透明蓝色覆盖在任意背景上模拟层级。

主题预设也必须走同一生成链路。常规预设使用 Tonal Spot，`simple-large` 使用官方 Monochrome 变体，`anthropic` 使用官方 Fidelity 变体保留品牌种子在容器中的辨识度；预设只覆盖颜色角色，不改变页面功能或工作区权限。

### 2.2 字体与排版

- 默认界面字体统一为 Google Sans Flex；简体中文由 Google Noto Sans SC 补字，两者均随前端资源自托管，不依赖外部字体 CDN。
- 代码、密钥、模型表达式和需要逐字符辨认的技术内容使用 Google Sans Code；普通价格、指标和统计数值继续使用界面字体，不得仅为对齐而切换到等宽字体。
- 现有字体选择器属于用户主动偏好；未主动选择 Serif 时，所有主题预设都使用上述 Google Sans 字体栈。
- 页面标题：`28px / 700 / 1.2`，窄屏 `22px`。
- 区块标题：`16px / 650 / 1.35`。
- 页面与内容区块统一使用单标题层级；标题下不再放副标题、标题释义或装饰性眉题。
- 模型描述、字段帮助、错误信息、空状态和风险提示属于业务内容，不按标题副文案删除。
- 正文：`14px / 400 / 1.5`；辅助文字：`12px / 400 / 1.4`。
- 数值使用 `font-variant-numeric: tabular-nums`，在不改变字体家族的前提下保证指标列对齐。
- 标题和标签不使用全大写作为装饰；产品文案全部来自既有 i18n key。

### 2.3 间距与尺寸

基础间距单位为 `4px`，常用节奏为 `8 / 12 / 16 / 24 / 32px`。

| 元素           | 尺寸                                  |
| -------------- | ------------------------------------- |
| 侧边栏         | 桌面 `256px`，折叠 `56px`             |
| 页面内容内边距 | 桌面 `32px`，平板 `24px`，窄屏 `16px` |
| 默认按钮       | `36px` 高，水平内边距 `14px`          |
| 紧凑按钮       | `32px` 高                             |
| 输入框         | `40px` 高                             |
| 导航项         | `40px` 高，圆角 `12px`                |
| 内容表面       | 内边距 `24px`，窄屏 `16px`            |

### 2.4 圆角与层级

- 工作台内容面：`20px`。
- 卡片、表格容器、弹窗：`16px`。
- 输入、按钮、标签：`10–12px`。
- 卡片默认无描边、无阴影；相邻区域通过画布底色、内容面和间距分层。
- 按钮默认无阴影；实心主按钮以颜色表达优先级，次要按钮以低对比填充或文字表达。
- 输入控件默认使用低对比填充面，不增加常驻描边；焦点和错误状态允许使用清晰描边或焦点环。
- 不使用渐变、玻璃装饰或悬浮阴影制造层级。
- 弹窗使用背景模糊、独立内容面和统一动效建立层级，不增加常驻描边或阴影。

## 3. 应用骨架

1. 认证后页面使用当前工作区的 `surface-container-low` 侧边栏 + `surface-container-lowest` 中性内容画布；桌面不重复渲染顶部导航栏。
2. 侧边栏依次包含品牌、搜索、分组导航、底部通知/语言/主题/用户操作。
3. 页面内容统一使用 `SectionPageLayout`：标题行、可选操作行、可滚动内容区、页脚区域。
4. 内容区的主卡片和共享数据表格采用当前工作区的浅色主题内容面，标题与操作同一行；页面画布不承载工作区色调。
5. 公共页面使用同一套内容宽度、按钮、卡片和页脚，不将认证后侧边栏强行带入登录/法律页面。
6. 禁止仅为了套用组件而产生卡片嵌套。需要同时呈现摘要、列表和图表时，优先使用同一内容面的分区、栅格或浅色子区域。

## 4. 组件契约

### 导航

- 激活项使用对应分组的 Material 3 `Container` 背景和 `On Container` 前景，不使用厚重黑底。
- 导航抽屉背景使用当前工作区动态色的 `surface-container-low`，并与使用 `surface-container-lowest` 的页面画布形成克制色差。
- 平台为主色蓝，聊天为青绿，常规为次级蓝灰，个人为琥珀，管理为珊瑚，系统管理为绿色；颜色只表达所在工作区，不改变权限或路由。
- 分组标题为 `12px` 中等字重、灰色，分组之间保持 `16px` 间距。
- 导航图标直接显示，不放入独立底色容器。
- 折叠、移动和抽屉状态必须保留可访问名称与焦点顺序。

### 表格与工具栏

- 工具栏先放主操作，再放搜索和筛选；筛选无结果时显示真实空状态。
- 表头与正文必须视觉分离：表头使用当前页面的 `primary-container / on-primary-container` 形成独立色带，正文首行保留 `16px` 间距；不得把表头和正文包成一块连续的有边卡片。
- 表头使用 `12px` 字号，正文行高不低于 `48px`。正文单元格内容统一由圆角胶囊承载，胶囊只包裹真实内容，不扩展成整格底色。
- 共享表格默认按列循环使用 `primary-container`、`secondary-container`、`tertiary-container`、`info-container`、`warning-container` 与 Neutral Surface 角色；有明确语义的列通过 `tableTone` 指定 `success`、`warning`、`error` 等角色。禁止在业务表格中手写原始颜色类。
- 选择列、操作列、空状态与跨列内容使用共享组件的紧凑或无胶囊规则，不得为适配视觉而破坏勾选、排序、固定列、展开和分页行为。
- 操作列使用图标按钮并提供 `aria-label`；危险操作使用红色实心按钮或危险菜单项。
- 不引入参考图中不存在的列、筛选器或汇总指标。

### 表单

- 标签、输入、帮助文本、错误文本保持垂直节奏；错误文本不替代字段标签。
- 主提交按钮右对齐或在移动端全宽；取消保持次要层级。
- 只改变呈现方式，不改变现有校验、字段和提交行为。

### 图标

- 图标直接放在文字、数值或操作旁，不添加彩色方块、圆形底板、渐变或阴影。
- 状态图标可使用对应语义色，但不得用额外容器模拟徽章；真正的状态标签继续使用 `Badge`。
- 纯图标按钮保留稳定点击区域，点击区域可透明或在 hover 时使用低对比底色，不显示常驻描边和阴影。

### 图表与指标

- 指标卡只显示实际返回的指标及其主值，不渲染虚构副标题。
- 图表容器使用白色内容面、浅网格线和语义色；普通用户隐藏管理员专属控制，已有权限逻辑保持不变。
- 图表切换使用紧凑分段控件，切换内容而不是复制两份组件。

### 反馈与弹窗

- 通知、确认、创建和配置弹窗共用统一表面、模糊背景、无常驻描边的结构和动效。
- 底部不再使用分隔线；一个按钮占满可用宽度，多个按钮平均排列并垂直居中。
- 破坏性操作使用实心红色，普通主操作使用实心主色，取消使用低强调按钮。

### 侧边抽屉

- 业务抽屉必须复用 `SheetContent` 或移动端 `DrawerContent`，不得在页面内重新实现定位、遮罩、圆角或进退场动画。
- 抽屉是使用共享 `rounded-2xl` 圆角令牌的悬浮内容面；窄屏距离对应视口边缘 `12px`，`sm` 及以上为 `16px`。左右抽屉的顶部、外侧和底部间距相等，上下抽屉的两侧与对应外侧间距相等。
- 每个抽屉保留业务需要的响应式 `max-width` 与内容高度；共享组件只约束其不超过扣除外边距后的安全视口。抽屉内部只能有一个明确的纵向滚动区。
- 抽屉内的业务区域使用 Material 3 `primary / secondary / tertiary container` 或 Surface Container 色阶分区，不使用分割线、描边卡片或卡片阴影。
- 左右、上下抽屉都必须从自身所在的视口边缘完整滑入。进场与退场统一使用 Material 3 emphasized `cubic-bezier(0.2, 0, 0, 1)`，保证运动始终“慢启动、加速、再减速”；进场时长 `420ms`，退场时长 `320ms`，确保首尾帧都连续。移动端 Vaul 手势抽屉保留其标准 iOS 非线性拖拽曲线。
- 遮罩的透明度与 `backdrop-filter` 同步渐变，不能在打开或关闭时硬切模糊。`prefers-reduced-motion: reduce` 下取消位移和模糊过渡，但不改变遮罩层级、焦点锁定与关闭行为。

## 5. 状态与可访问性

- 所有交互控件提供 hover、focus-visible、disabled、loading 和错误表达。
- 键盘焦点使用清晰的 `--ring` 描边；颜色对比度以 WCAG AA 为最低目标。
- 任何滚动区域都必须有明确的高度约束和单一滚动轴，避免卡片内部出现意外纵向滚动条。
- 减少动画时遵循 `prefers-reduced-motion`，不影响内容和操作完成。

## 6. 实施顺序

1. 令牌、字体、画布、侧边栏和页面布局。
2. 按钮、输入、卡片、标签、Tabs、表格、空/错/加载状态。
3. 数据看板、模型广场、密钥、日志、用户、钱包、个人资料等页面族。
4. 系统设置、渠道和复杂弹窗。
5. 公共/认证/法律页面与移动端断点。

每一层都必须通过类型检查、lint、生产构建和浏览器视觉检查后再进入下一层。
